# ADR-0008: 料金は出典付きの表から整数で計算し、日次集計は UTC の日で行う

- **ステータス**: 採択
- **日付**: 2026-09-20

## 背景

Step2 の受け入れ基準は「料金計算の単体テストがベンダー公表単価と誤差 0」「1 万件投入で集計 SQL ≦ 1 秒」。料金は請求の根拠になるため、計算の誤差と「いつの単価か分からない値」の両方を避けたい。

## 決定

### 料金

- **単価の正本は `src/domain/pricing/vendor-prices.json`**。1 行が `{provider, model, inputUsdPerMillionTokens, outputUsdPerMillionTokens, source, retrievedAt}` で、単価は **10 進の文字列**（`"3.00"`）。`source` は公表ページの URL、`retrievedAt` は確認した日。
- **JSON をコードの隣（`src/domain/`）に置く**。これは読み物ではなく実行時に読む設定で、プロキシが中継のたびに参照する。`docs/` に置くと配備物に含まれる保証が無くなる。
- 読み込み時に壊れた行（未知のプロバイダ・単価が読めない・出典や取得日が無い・重複）があれば**例外で落とす**（fail-closed）。黙って読み飛ばすと、その行のモデルが「未対応」に化けて中継だけが止まり、原因が表に出ない。
- **計算はすべて BigInt**。単価はマイクロ USD（1 USD = 10^6）へ変換してから掛け、100 万トークンで割る。端数は**切り上げ**（1 トークンでも使った呼び出しの料金を 0 にしない）。
- 単価の文字列 → マイクロ USD の変換は `src/domain/money.ts` の `parseUsdDecimalToMicro`。小数 6 桁を超える値は「マイクロでは表せない」として拒否する（丸めて受け取ると「誤差 0」が静かに崩れる）。
- **「誤差 0」は `tests/pricing.test.ts` が固定する**。期待値は実装の関数を使わず、正本 JSON の文字列から別の書き方（文字列連結で整数化し、割った余りで切り上げ）で組み立てて突き合わせる。ゲート（`gate:step2`）は**正本 JSON からテスト名を導いて**、全モデル分が pass しているかを見る（モデルを足してテストを書き忘れたら落ちる）。

### 日次集計

- **日の境目は UTC**。配備先のタイムゾーンで変わると、同じデータの日次集計が環境によって変わる（請求の根拠が環境依存になる）。テナントごとの表示タイムゾーンは Step5 の表示の都合として扱う。
- 期間（`from` / `to`、どちらも含む）は**必須**で、上限は `USAGE_RANGE_MAX_DAYS`（366 日）。無指定の全期間は全件走査になる（§8 / §9）。
- 集計は 1 クエリ。`date_trunc('day', "createdAt" AT TIME ZONE 'UTC')` を**タグ付きテンプレートの `$queryRaw`** で書く（値はすべてパラメータ。`guardRawSql()` が許すのはこの形だけ）。`@@index([tenantId, createdAt])` がそのまま効く。
- memory アダプタは同じ規則（`src/domain/usage-window.ts`）で JS 集計し、**両者が同じ結果になることを契約テストが固定する**。
- 料金の合計は BIGINT のまま返し、DTO では文字列で運ぶ（`docs/spec.md` §3 の金額の扱いと同じ）。件数・トークン数は数値にするが、安全な整数の範囲を超えたら落とす（黙って丸めない）。

## 理由

- 単価は外部の事実なので、写しを持つこと自体は避けられない。避けられるのは「いつ・どこから写したか分からない」状態で、`source` と `retrievedAt` を必須にすることでそこを閉じる。
- 浮動小数を 1 か所でも挟むと「誤差 0」は保証できない。BigInt に統一すれば、桁数が増えても丸めが起きない。
- UTC 固定は「同じ入力なら同じ集計」を最優先した結果。表示の都合は後段で吸収できるが、記録と集計が環境依存だと後から直せない。

## 結果

- モデルを増やすときは JSON に 1 行足すだけでよい（テスト名とゲートの照合は正本から導かれる）。単価を更新するときは `retrievedAt` も一緒に更新する。
- **単価の値そのものが正しいかは機械では確かめられない**（公表ページを読みに行く経路をアプリに持たせない）。出典 URL と取得日を人が確認するのが唯一の手段で、値を変える差分はレビューで出典と突き合わせる。
- 集計の性能は `scripts/bench-usage-aggregate.ts` が 1 万件で測る（実測 15ms / 上限 1 秒）。
